# 古风五子棋 参考图复刻 — 设计文档

- 日期：2026-08-14
- 作者：与用户协作 brainstorming 产出
- 范围：在现有 Phase 1 网页版基础上，按微信小游戏风格的参考图**完整复刻**视觉与运营系统：视觉换肤、段位系统、双货币（金币/卷轴）、商店、每日签到、幸运转盘、看广告双倍（网页用模拟广告）。
- 参考图：主页(7)、对局(8)、失败(9)、胜利(10)、段位进阶(11)、商店(12)、每日签到、幸运转盘（用户提供）。
- 现状基线：见 `2026-08-13-wzq-gomoku-web-design.md`。当前只有 `经验/等级(Lv1-5)`，无段位/货币/商店/广告。

## 0. 目标与非目标

**目标**：让网页版在观感上贴合参考图（古风 + 小游戏运营皮），并落地真实可玩、可持久化的段位与经济系统。

**非目标（本次不做）**：
- 失败弹窗里的「其他游戏广告」宫格 —— 用户明确先不展示。
- 真实 IAA 广告接入 —— 网页无广告 SDK，用**模拟广告弹窗**（播放条 3s）代替，发放同样的双倍奖励。
- 微信登录/分享/小游戏生命周期 —— 网页不适用。
- 好友热玩宫格 —— 不展示。

## 1. 分阶实现（A → B → C → D）

本设计书覆盖全部愿景，实现按四阶推进，每阶可独立验收；每阶各自走 plan → 实现 → 验证循环。

| 阶段 | 主题 | 交付 | 依赖 |
|---|---|---|---|
| **A** | 视觉换肤 | 主页/对局/胜负/段位进阶 画面贴合参考图 + seedream 新素材；段位/金币/卷轴先**占位展示** | 无 |
| **B** | 段位系统 | 段位阶梯+积分，三模式结算接入，Game 顶部与胜负弹窗显示真实段位，段位进阶界面接真实数据 | A |
| **C** | 双货币 + 商店 | 金币/卷轴余额与奖励结算、看广告双倍（模拟）、商店页（棋盘/头像框/落子 三类，金币价+卷轴价，拥有/装备） | B |
| **D** | 签到 + 转盘 | 每日签到（7 天循环）、幸运转盘（消耗金币，概率产出金币/卷轴/皮肤券） | C |

## 2. 段位系统（阶段 B）

### 2.1 阶梯
从低到高、数字越大越强（与参考图「业余1级 → 业余2级」为升段一致）：

```
索引  0..8   业余1级 … 业余9级
索引  9..17  业余1段 … 业余9段
索引  18     大师
```
共 **19 阶**。新用户起始 `tier=0`（业余1级），`points=0`。

### 2.2 积分与升降段
- **胜 +10 分，负 −10 分**（五子棋和棋极少，忽略；如出现按 0 分处理）。
- 每阶晋级阈值 `threshold(tier)`：业余级(0–8)=**30**，业余段(9–17)=**50**，大师(18)=不封顶（`points` 只累计展示，不再升段）。
- **升段**：`points >= threshold` → `tier += 1`，`points -= threshold`（溢出带入新段），触发「段位进阶」界面。
- **降段**：`points < 0` → 若 `tier > 0`：`tier -= 1`，`points = threshold(tier) - 10`；若 `tier == 0`：`points` 夹为 0（业余1级为地板，不降级、不出现负分）。
- 参考图胜方「10/30 ↑+10」、负方「-40/10 ↓−10」中的具体数字不逐一对齐，以本模型为准（进度条显示 `points/threshold`）。

### 2.3 权威计算位置
段位阶梯与升降段规则以**一份 Go 实现为唯一权威**（`internal/rank`）。TS 侧只保留一份**展示用镜像**（阶名、阈值），用于结算前的乐观展示与文案；真实结果以服务端返回为准。

### 2.4 与经验/等级的关系
`经验/等级` 字段**保留**（仍用于人机难度扣费等既有内部逻辑），前端不再展示，改为展示段位。

## 3. 双货币与结算（阶段 C）

### 3.1 货币
- **金币 coins**（常规）：来源＝胜利、签到、转盘产出；用途＝转盘抽奖、购买普通皮肤/头像框/动效。
- **卷轴 scrolls**（稀有）：来源＝签到、转盘产出；用途＝购买高阶皮肤、高阶头像框/动效。

### 3.2 对局奖励
- 胜 **+120 金币**；负 **+0**。
- 残局首次通关：易 **+60** / 中 **+100** / 难 **+150** 金币（按现有难度分档）。
- 卷轴不由对局直接产出（仅签到/转盘）。

### 3.3 看广告双倍（模拟）
- 胜利结算响应带一次性 `rewardId`。
- 点「看广告双倍领取」→ 前端弹**模拟广告弹窗**（3s 播放条，播完出现「领取」）→ 调 `POST /api/reward/double {rewardId}`。
- 服务端校验 `rewardId` 未消费过则再补发**等额金币**（合计 2×，如 120→240），标记已消费。**每局仅一次、幂等**。
- 签到「视频双倍领取」同理（当日奖励×2，每日一次）。

## 5. 每日签到（阶段 D，参考图）

- 7 天循环网格 + 第 7 天「累计登录 7 天 神秘大奖」宝箱。
- 默认奖励表：

| 天 | 奖励 |
|---|---|
| 1 | 金币 ×100 |
| 2 | 直接解锁高阶皮肤 `gold`（流金岁月）；若已拥有 → 折算卷轴 ×30 |
| 3 | 卷轴 ×10 |
| 4 | 金币 ×200 |
| 5 | 卷轴 ×20 |
| 6 | 金币 ×300 |
| 7 | 宝箱：金币 ×500 + 卷轴 ×30 |

- 规则：按**自然日**（服务器本地日期）每日一领；`checkin_streak` 记录连续天数，取 `((streak) mod 7)+1` 作为今日档位。断签（隔日未签）`streak` 归零重新从第 1 天。
- 底部：`领取奖励` + `视频双倍领取`（模拟广告，当日奖励×2，每日一次）。

## 6. 幸运转盘（阶段 D，参考图）

- 8 扇区圆盘 + 中心指针，底部 `金币 ×100/次`，`抽奖` 按钮。
- **消耗金币抽奖**，产出金币/卷轴（大奖含皮肤券）。奖池默认（服务端加权，权重可配）：

| 扇区 | 奖励 | 权重 |
|---|---|---|
| 1 | 金币 ×50 | 22 |
| 2 | 金币 ×80 | 20 |
| 3 | 金币 ×100 | 16 |
| 4 | 金币 ×300 | 6 |
| 5 | 卷轴 ×20 | 16 |
| 6 | 卷轴 ×50 | 10 |
| 7 | 卷轴 ×100 | 6 |
| 8 | 大奖：卷轴 ×500 | 4 |

- 服务端按权重随机决定中奖扇区并结算，返回扇区 index；前端指针动画停到该扇区。
- 金币不足时禁用抽奖并提示。

## 9. 后端改动（阶段 B/C/D）

### 9.1 数据模型（`internal/store`）
`users` 增列：
```
rank_tier        INT  DEFAULT 0
rank_points      INT  DEFAULT 0
coins            INT  DEFAULT 0
scrolls          INT  DEFAULT 0
equipped_skin    TEXT DEFAULT 'wood'
equipped_frame   TEXT DEFAULT 'none'
equipped_effect  TEXT DEFAULT 'default'
last_checkin     TEXT DEFAULT ''      -- 上次签到自然日 YYYY-MM-DD
checkin_streak   INT  DEFAULT 0
```
新增拥有关系表 `owned_items(uid, item_type, item_id)`，唯一索引 `(uid,item_type,item_id)`。
新增双倍幂等表/内存 `consumed_rewards(reward_id)`（或复用房间内存态）。

迁移：新增列用 `ALTER TABLE ... ADD COLUMN`（SQLite/MySQL 均兼容默认值），兼顾并发安全（见全局约定）。

### 9.2 新增 `internal/rank`
段位阶梯表 + `Apply(win bool, tier, points) -> (tier', points', promoted, demoted, delta, threshold)`，供人机上报、真人 game_over、残局通关统一调用。附单元测试覆盖升段/降段/地板 clamp/溢出带入。

### 9.3 接口
- `POST /api/ai/result`（扩展 `reportAiResult` 返回）：`{rankBefore, rankAfter, promoted, pointsDelta, rankProgress, rankThreshold, coinsDelta, coins, scrolls, rewardId}`。
- 真人 `game_over`：服务端更新段位/金币后，通过 ws 下发结算详情（或前端 `GET /api/me` 拉取）。
- 残局通关接口扩展奖励字段。
- `POST /api/reward/double {rewardId}` → 幂等补发。
- `GET /api/shop` → 三类目录 + 拥有/装备 + 金币/卷轴余额。
- `POST /api/shop/buy {itemType,itemId}`；`POST /api/shop/equip {itemType,itemId}`。
- `GET /api/checkin` → 7 天配置 + 今日可领 + streak；`POST /api/checkin/claim {double?}`。
- `GET /api/wheel` → 奖池 + 费用；`POST /api/wheel/spin` → 扣金币、返回中奖 index + 奖励。

所有涉及余额/段位/签到的写操作在服务端做校验与并发加锁，防止客户端伪造。

### 9.4 前端路由/状态
- 新增路由：`/shop`、`/checkin`、`/wheel`。
- `store/game.ts` 或新增 `store/user.ts` 持有 段位/金币/卷轴/装备 状态，结算后同步。
- 装备的 `skin/frame/effect` 驱动 BoardCanvas 与全局头像渲染。

## 10. 测试策略

- **后端**：`internal/rank` 升降段单测；商店购买（余额不足/重复购买/装备未拥有）；签到（每日一领/断签重置/双倍幂等）；转盘（扣费/权重分布抽样）；双倍幂等。
- **前端**：段位展示镜像与服务端一致性、结算弹窗文案、商店装备切换、转盘指针停位映射。
- **手动**：三种模式各跑一局验证段位/金币结算与升段界面；商店购买装备后对局生效；签到/转盘领取；模拟广告双倍。UI 在浏览器实机走查关键路径与边界（无法自动化的视觉部分显式说明）。

## 11. 关键取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 段位权威 | Go 一份，TS 镜像展示 | 防作弊，结算以服务端为准；与现有「真人服务端裁判」一致 |
| 广告 | 网页模拟弹窗 | 无广告 SDK，但保留双倍奖励玩法与幂等结算 |
| 双倍幂等 | rewardId 一次性消费 | 防重复领取，人机/真人/签到统一机制 |
| 横幅文字 | guqi 字体 + CSS 渐变叠木牌底 | 减少 seedream 生成量，文案可改不重出图 |
| 棋盘立体/转盘 | Canvas/SVG 程序化 | 可参数化、随主题变化、体积小 |
| 经验字段 | 保留但不展示 | 复用既有难度扣费逻辑，避免破坏性改动 |
